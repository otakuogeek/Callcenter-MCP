🏥 Flujo de Agendamiento — Biosanar IPS

Versión Feb 2026

🌐 Canales de Entrada

El sistema recibe solicitudes de citas por 4 canales: el bot de WhatsApp "Valeria" (canal principal), el portal web público para pacientes, el panel administrativo interno y el servidor MCP para agentes de inteligencia artificial.

📱 WhatsApp → Baileys v7 (WebSocket directo a WA)
🖥️ Portal → React 18 + Vite en puerto 8080
🤖 MCP → Protocolo JSON-RPC 2.0 en /mcp-py*
⚙️ Admin → API REST autenticada con JWT

🪪 Paso 1 — Identificar al Paciente

Cuando un paciente escribe por WhatsApp, el motor de IA analiza su mensaje para entender qué necesita. Si quiere una cita, el bot le pide su número de cédula, lo busca en la base de datos, y si no existe, lo registra pidiendo nombre, teléfono y EPS.

🧠 LLM: Groq · LLaMA 3.3 70B
🔍 Función: searchPatient(document)
➕ Registro: registerPatientSimple()
📋 Resultado: patient_id listo para agendar

📅 Paso 2 — Consultar Disponibilidad

El sistema consulta las agendas médicas activas. Solo muestra fechas futuras (≥ hoy), agendas sin pausa y con cupos libres. Convierte los horarios de UTC a hora colombiana (−5h) y excluye los slots ya ocupados.

📊 Función: getAvailableAppointments()
🗄️ SQL: WHERE date ≥ CURDATE() AND status='Activa'
    AND is_paused=0 AND capacity-booked>0
⏰ Zona: UTC → America/Bogota (−5h)

🎯 Paso 3 — Seleccionar la Cita

Se presenta al paciente la lista de especialidades disponibles, luego el doctor (automático si solo hay uno), la fecha (máximo 5 opciones) y finalmente el horario específico en formato 12h (AM/PM) hora Colombia.

🏥 Filtro: especialidad → doctor → fecha → hora
🕐 Función: getAvailableTimeSlots()
📆 Máx opciones de fecha: 5
⏱️ Formato: HH:MM AM/PM hora local

✅ Paso 4 — Agendar la Cita

Al confirmar, se crea la cita dentro de una transacción MySQL para evitar conflictos. Se bloquea la fila con FOR UPDATE, se verifica que queden cupos, se inserta la cita y se incrementa el contador de slots ocupados. Si es cita doble, se crea automáticamente una segunda consecutiva.

💾 Función: scheduleAppointment()
🔒 Locking: SELECT ... FOR UPDATE
📝 Insert: appointments.status = 'Confirmada'
📈 Update: booked_slots += 1
📋 Doble: crea 2ª cita con hora + duration_minutes

⏳ Lista de Espera

Si no hay cupos, se ofrece inscribir al paciente en la lista de espera. El paciente elige la prioridad (urgente, alta, normal o baja) y el sistema le asigna una posición en la cola. Será notificado automáticamente cuando se libere un cupo.

📥 Tabla: appointments_waiting_list
⚡ Niveles: urgent | high | normal | low
📊 Posición: ordenada por priority + FIFO
📲 Notificación automática al liberar cupo

🔄 Reasignación Automática

Cuando un paciente cancela su cita, el sistema verifica si hay pacientes en lista de espera para esa especialidad. Si los hay, asigna el cupo al primero según prioridad y orden de llegada (FIFO), y le notifica por SMS o WhatsApp.

🚫 Trigger: cancelación libera cupo
📤 Endpoint: /assign-from-queue
🔢 Orden: priority_level ASC, created_at ASC
📲 Envío: SMS (LabsMobile) o WhatsApp

💾 Estado en Memoria (WhatsApp)

El bot mantiene el contexto de cada conversación en un mapa en memoria, indexado por número de teléfono, con un tiempo de vida de 2 horas. Almacena los datos del paciente, la especialidad elegida, las citas disponibles (filtradas para excluir fechas pasadas), el doctor y la agenda seleccionada.

🗂️ Estructura: Map<phone, StateContext>
⏱️ TTL: 2 horas
🔄 Filtro: filterPastAppointments()
📋 Campos: patientId, specialty, appointments, doctor, availabilityId

🧹 Auto-Limpieza de Base de Datos

Al arrancar el servidor y cada 24 horas, se ejecuta una limpieza automática que marca como "Completa" todas las agendas cuya fecha ya pasó. Esto evita que el sistema ofrezca citas en fechas anteriores a hoy.

🚀 Momento: arranque de server.ts + cron 24h
🗑️ SQL: UPDATE availabilities SET status='Completa'
    WHERE date < CURDATE() AND status='Activa'
⏰ Intervalo: setInterval(fn, 86400000)
